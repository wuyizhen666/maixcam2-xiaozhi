# SIoT 触屏监控 App

运行于 MaixCAM2 640×480 屏幕，独立于 SIoT 服务端；退出页面不会关闭 broker。MaixCAM2 供电并接入局域网后，本机监控与局域网 MQTT 收发不依赖 PC 或互联网；云端小智对话仍需外网。

## 界面与输入

主题/图表版已有真机验证，媒体摄像头和小智视觉转发已有实测，最新清空数据、图片识别界面与退出生命周期仍在测试，范围见文末：

- 左侧选择主题，底部为“新建主题”和“删除主题”；删除需要二次确认并显示完整主题名，会同时删除该主题历史。
- 左上提供搜索、清除筛选与刷新；左右两侧可滑动或拖动滚动条浏览，点击在松手时触发，防止滚动误选。
- 右侧底部为“消息”“图表”“图像/视频”和缩小后的“编辑/发送”。点消息查看详情，可复制到编辑器。纯数字消息显示折线与最新值、最小值、最大值；非数字或混合消息提示回到消息视图，不生成虚假数据点。
- “清空数据”需要二次确认，清除历史与旧缓存但保留主题，新消息继续显示；“删除主题”则连主题一起删除。
- “图像/视频”二级页提供所选 MQTT 主题图片、局域网收发、本机摄像头三种来源。“局域网收发”三级页可选择接收端填写 HTTP 图片/MJPEG/RTSP 地址，或发送端显式共享本机摄像头。本机摄像头先选择 JSON / Base64 与 2 / 5 / 10 fps，默认 5 fps，切换先停止旧会话；两种格式均可配置当前会话速率。详见 [媒体协议与双机连接](../../docs/SIOT_MEDIA.md)。
- 小智拍照 MCP 先向图片主题发原始 JPEG，云识别结束后以同一 `capture_id`、同一原图更新 `recognition`，另向结果主题发送文字和状态，不等待 SIoT 发送确认或改变原云端返回。默认主题为 `username/vision/image`、`username/vision/result`，可用监控配置的 `vision_image_topic`/`vision_result_topic` 覆盖；小智配置 `siot_vision_publish: false` 可关闭。

消息列表和详情显示完整 `YYYY-MM-DD HH:MM:SS`，采用设备本地时区；实时消息使用本机接收时间，历史消息使用服务器记录时间。图表保留同秒数据的实际时间，不人为添加时间间隔。

编辑器以英文大小写、数字、常用符号和中文快捷词为主，支持空格、换行和光标移动，不包含完整拼音输入法。蓝色“退格删字”删除光标前一个字符，中文、英文、数字均可；“清空”删除当前输入框全部内容。选择主题或正文输入区后输入，按发送等待反馈，按完成回到消息页。

## 收发与保存

- 保存开启时，主题必须以配置账号的 `username/` 开头。后台先查找主题，不存在时通过 `PUT /api/v2/topics` 提交去掉账号前缀的相对名称，确认完整主题名后以 QoS 1 发布。登记失败不发送、不静默降级；仅设置 QoS 1 不能保证未登记主题被保存。
- 保存关闭时以 QoS 0 发布普通具体主题，允许不带账号前缀；均不发送 retained 消息。
- 反馈区分排队、主题登记、MQTT 确认与失败。确认表示 broker 接收与保存请求，持久化需历史回读确认，也不表示其他设备已收到或执行。等待确认时禁止重复点击发送。
- QoS 1 恰遇断线且 Paho 已接受排队时，保持请求等待重连确认，不误报未发送或自行重复发布；离线时拒绝新的发送。
- MQTT 实时订阅与 HTTP 历史读取独立，网络线程不绘制界面。历史读取失败不阻塞实时 MQTT；连接断开自动重连。
- 最多 64 个主题，每主题 50 条缓存；主题最多 128 UTF-8 字节、发布正文最多 2048 字节，详情最多显示 4096 字节，接收队列有界。

主题删除使用 `DELETE /api/v2/topics/{numeric_id}`，不带正文。真机临时主题测试确认该操作会同步清除历史，因此界面二次确认不能省略。

局域网发送端显式开启后默认监听 `8090`（配置 `media_http_port` 可改）：`/` 是浏览器预览，`/snapshot.jpg` 为原 JPEG，`/stream.mjpg` 为连续帧，`/status.json` 为状态。接收设备填写发送设备的完整 LAN URL。最多 4 个媒体/8 个总连接、10 fps 上限，无录像或持久存储，退出停止 HTTP 服务与摄像头；它不是 RTSP server。SIoT 的 `8080` 数据库历史页面不用于看连续视频。

若账号为 `siot`，本机 MQTT 连续帧默认发 `siot/camera`；小智云识别原图和结果则为 `siot/vision/image`、`siot/vision/result`。应选对来源与主题，QoS 0 连续帧不请求历史保存，不能用历史页空白判断没有实时发送。

界面“Base64”实际发送完整 `data:image/jpeg;base64,` 加 JPEG Base64 的 Data URL。当前用户的 Mind+ 版本裸 Base64 破图，带前缀单帧及连续画面已确认正常；MaixCAM2 接收器另兼容自动识别裸 Base64。`MediaPublisher` 单独控制发送速率，`MediaSession` 每遇新帧就更新 latest 槽，不重复限速。

连续摄像头 JPEG 仍限 512 KiB；小智原图允许 2 MiB，图片信封与媒体接收包允许 3 MiB，解码图片限 2 MiB。识别文字最大 256 KiB，原 MQTT 内容不因屏幕限制而截断；界面预览前 512 字符最多三行，识别详情最多 4096 UTF-8 字节，超限有提示。

实时发送 JPEG 保持 320×240、quality 75，本轮没有降质；本机预览 NEAREST 放大只影响 LCD。小智拍照仍保持 640×480 原 JPEG。字体/标签缓存、快速缩放及 10 ms 媒体循环用于降低 UI 开销；渲染 profile 只有 `/tmp/siot-monitor-profile` 标记存在时采集 30 帧并输出本地摘要。

## 配置与运行

配置位于 `/etc/siot/monitor.json`，格式见 `connection.example.json`。真实凭据不应进入代码或 Git。`default_topic` 填写实际账号前缀，例如账号为 `alice` 时使用 `alice/monitor`；省略时按当前账号生成。

依赖设备已有的 Pillow、Paho MQTT 2.x 和 MaixPy；RTSP 使用设备已有 ffmpeg，不安装旧 `siot-0.1.7` 客户端或新增依赖。`launch.py` 临时协调小智弹窗与触摸 UI 所有权，不修改持久开关；主程序不控制 systemd、不创建音频对象。本机摄像头在独立进程中运行，与小智拍照共享协作锁，第三方原生 App 不参与；切换来源或退出时停止采集与发送。当前 Maix 启动路径要求包装器成功时自然结束，非零返回抛出异常，避免桌面误报 `code:-1`；这不限制其他 Python 程序使用 `sys.exit`。

首次绘制或出现 `/tmp/siot-monitor-capture` 标记时，保存预览到 `/tmp/siot-monitor/preview.jpg`，用于本地检查，不上传。
