# 摄像头与补光灯 MCP 接入设计

用户要求：补全现有 MaixCAM2 小智的摄像头、补光灯 MCP 接入，并延续当前设备开发与实测。

## 方案

沿用现有 WebSocket / JSON-RPC 内置 MCP，不新增进程常驻服务或依赖。摄像头采用小智官方 `self.camera.take_photo(question)` 协议：接收 initialize 中的 vision 能力，按请求拍摄 JPEG，上传至协商的视觉分析接口，将真实分析结果返回云端。补光灯使用已实测的 B25/PWM6。

考虑过仅返回本地 JPEG 路径：云端无法读取，不能完成“看看眼前物体”。也考虑过独立摄像头常驻服务：本机共享 Maix 多媒体资源有冲突历史，增加部署和恢复复杂度。选择在现有小智进程内按需调用硬件，用工作线程处理拍摄与 HTTP，保持 asyncio 循环响应。

## 工具

- `self.camera.take_photo(question: string)`：按需拍照并回答指定问题；无 vision 能力时明确报错，不拍摄/上传。
- `self.camera.get_status()`：报告视觉接口是否已配置、最近一次拍摄结果摘要；不返回凭据。
- `self.light.set_power(enabled: boolean)`：开启默认 25% 补光或关闭；重新开启恢复上次非零亮度。
- `self.light.set_brightness(brightness: integer 0..100)`：设置亮度，0 为关闭。
- `self.light.get_status()`：查询驱动回读的开启状态、亮度。

保持原有 5 个工具及其行为。新工具参数严格验证，失败返回 isError。相机并发请求串行化，图像大小限制，网络连接和读取有超时；不把令牌或图片内容写入日志。拍摄默认 640×480、JPEG quality=80，照片只在临时内存/目录中存在。

## 生命周期与验收

摄像头按请求创建/关闭；补光灯懒初始化，服务停止时关闭并释放。增加 systemd ExecStopPost 的仅针对本服务所拥有灯通道的关灯兜底。保留原启用状态与音量；不顺带修复配置轮询和其他既有问题。

验收层级：主机行为测试 → 设备端协议/驱动测试 → 真实云端 tools/list 与 tools/call → 拍摄视觉回答、灯状态回读、原语音/屏幕回归。部署前校验目标身份及源文件哈希，备份改动文件；失败恢复原文件和服务。

授权与选择：用户的自主执行约定免除常规实现确认；本设计中的协议、分辨率、工具命名为实现选择。修改在用户指定的独立项目目录、新分支 `codex/camera-light-mcp` 内完成，已有基线/测试文档保留，不另建工作树。
