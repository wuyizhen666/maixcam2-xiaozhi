# 拍照偏色与亮度异常修复

用户反馈：拍照有严重偏色，也有过亮/发白或过暗现象。

## 当前证据

同一次打开相机，默认第8帧约0.292秒：RGB均值171.88/164.35/157.35，任一通道≥250的像素比例12.82%。第30帧约0.89秒后，到120帧约2.59秒整体稳定，饱和比例约0.6%。明确启用AE/AWB后第8帧仍偏亮，单设自动模式不足以代替预热。

SDK红绿蓝色块JPEG/PNG编码通道正常；同帧JPEG与PNG全图通道均值差不足0.1灰度值，没有支持“红蓝通道互换”的证据。图像变化支持启动自动成像尚未稳定；不能只凭曝光/gain getter值断定实时AE收敛。

## 修复选择

每次打开相机后明确设置 AeMode.Auto 和 AwbMode.Auto，持续读帧，至少30帧且经过2秒后才保存当前帧。预热总预算5秒，每次read按剩余预算限制block_ms，失败显式报错并关闭相机。不固定曝光时间、增益、白平衡常数，不做后处理调色。

这是当前设备实测与官方v4.12.5跳过初始30帧建议之上的保守时间门槛，不宣称所有光照条件都保证收敛。保持JPEG质量、同图上传/3秒预览、MCP协议不变。照片出现会比原版晚约1–2秒，预览自身仍保持3秒。

## 验证步骤

- [x] 回归测试先复现：过早保存、自动模式未设置、低帧率帧数不足、无界等待；覆盖异常关闭。
- [x] 实现最小修改并运行完整主机/板端测试，独立审查。
- [x] 目标文件哈希预检和备份后部署。
- [x] 同场景多次冷启动采样，比较旧第8帧与修复帧；真实MCP拍照/屏幕预览回归。
- [x] 保留原设备开关/音量，报告成像证据与尚不能确认的光照/光学色彩边界。

四项新增回归先失败后通过；完整主机/板端各41项通过。三次冷启动耗时2.55–2.66秒，接近饱和像素占比0.78%–0.92%。真实MCP成功、预览约3.099秒且屏幕像素匹配，用户明确反馈“刚才看到图片颜色正常了”。
