# 拍照预览与 MCP 调用提示

用户需求：拍照时显示同一张照片 3 秒后消失；调用 MCP 时在屏幕下方显示具体工具名称。继续在当前功能分支增量实现、部署验证，不改硬件接入协议。

## 设计选择

复用现有 `popup.rgba` 合成通道，避免新建显示实例。照片等比例放在顶部操作条和底部提示条之间，预览期间暂时代替聊天气泡；底部显示完整 `self.*` 工具名，执行期间持续显示，结束后保留 3 秒。仍遵守现有弹窗开关和关闭操作。

照片在 JPEG 采集成功时立即通知事件循环，不等待视觉服务器回复；UI 回调使用上传的同一份 JPEG。预览计时从实际绘制提交完成后开始，3 秒后主动重绘，即使没有新的聊天事件也会清除。连续拍照重新计时，旧定时器不得清掉新照片。

新增一个小型 `UiFeedback` 状态管理器负责工具/照片生命周期，绘图仍在 `ui_render.py`。照片通知通过事件循环线程执行，旧会话的迟到回调被丢弃；会话关闭、总开关关闭或关闭弹窗时立即清理反馈。并发工具以最近发起者为当前提示，结束保持期内也可看清瞬时调用。

## 实测调整

- 主机和板端各 37 项 Python 测试通过。第一轮 UI 状态记录预览持续 3.156 秒，但实际合成帧没有照片，不能据此验收显示成功。
- 定位原 C loader 只比较秒级 mtime+size，导致同秒 JPEG 预览写入被忽略。新增实际 loader 原生回归，旧代码红；修复缓存键为 mtime 秒/纳秒+inode+size，3 项原生断言通过。
- 因此需对既有注入层做小范围刷新判断修复并重新加载，方案从“无需变更注入层”调整为“保留同一协议，修复版本识别”。已独立审查，通过。
- 预检发现用户已将 enabled 改为 true；本次以最新设备状态为恢复基线，不再沿用上一轮 enabled=false。
- 修复注入层后复测：照片可见状态 3.168 秒，预览区采样像素与实际合成帧匹配 100%，消失后匹配 0%；MCP 工具名称清晰显示。前后图已人工查看。
