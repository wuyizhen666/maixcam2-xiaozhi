## 已完成的主要改动

### 摄像头、补光灯与屏幕反馈

- 按需拍摄并释放相机；相机工具仍采用已协商的云端视觉服务，不是离线模型推理接口。
- 摄像头打开后启用自动曝光与白平衡，至少读取 30 帧并等待 2 秒，减少启动阶段发白、偏色。
- 拍照预览使用实际提交分析的同一张 JPEG，显示 3 秒后恢复；工具调用期间和结束后短时间保留名称提示。
- 修复原生叠加层对同秒文件更新的识别，避免预览图已写入而屏幕未及时加载。
- 补光灯具有状态回读、占用判断及停止时清理。

资料：[摄像头/补光灯验收](CAMERA_LIGHT_MCP_VALIDATION.md)、[颜色修复](CAMERA_COLOR_FIX.md)、[预览与 MCP 提示](PHOTO_PREVIEW_MCP_FEEDBACK.md)。

### 外设 MCP 与 IMU

- 新增板载 LED、按键只读事件、IMU、RTC、ADC 原始读取及受策略限制的外部 I/O。
- 外部 I/O 默认不开放；通过本地逻辑目标白名单指定资源，不接受任意设备路径或任意引脚复用。
- IMU 大面板与底栏实时更新，生命周期跟随会话和显示状态；防止并发调用产生重复采样循环。
- 新增 `self.imu.calibrate_gyro`、`self.imu.get_calibration`、`self.imu.clear_calibration`。校准约 3 秒，明显运动、样本不足或保存失败时不替换旧结果。
- 校准后静止观测中，三轴平均角速度绝对值均低于 0.02°/s；这只是本次桌面静止结果，不是全温度精度保证。
- 按键读取不独占系统按键，并处理 Maix 默认退出监听对后台服务的影响。

资料：[外设验收](PERIPHERAL_MCP_VALIDATION.md)、[I/O 策略](IO_ACCESS.md)、[IMU 实时与校准](IMU_LIVE_CALIBRATION.md)。

### 唤醒、退出及音频修复

- 修正原始竖屏触摸坐标与横屏 UI 的映射；X 结束当前对话并收起弹窗，背景服务继续运行。
- 关闭前排队的旧点击不能重新打开弹窗；KWS 每次解码后检查命中，避免后续空结果覆盖已有唤醒词。
- 关闭会话先恢复本地唤醒流与界面，再等待网络连接关闭，避免旧连接迟到清理影响新会话。
- 触摸唤醒改为指定圆标位置连续按住 2 秒。读取真实 MT 槽位而非无效普通坐标快照；松手、移出或多指取消计时，一次持续按住只触发一次。
- 依据真实触摸记录，将圆标热区限定为左上 52×48 像素，覆盖设备在圆标处报告的边缘坐标；没有改成全屏触摸唤醒。
- 修正静音逻辑误改采集增益的问题。播放音量现在只缩放待播放 PCM，静音输出等长零样本，不再写入共享输入增益。
- 本日音频修复阶段主机与板端各 153 项测试通过；另有用户真实声音和手指操作确认。交付前的重新验证结果以最终提交记录为准。

资料：[触摸与重唤醒修复](TOUCH_CLOSE_FIX_2026-10-25.md)、[音频静音隔离修复](AUDIO_MUTE_CAPTURE_FIX_2026-10-25.md)。

## 离线模型、App 与实时性实验

用户验收目标为：每个模型稳定至少 20 次/秒、最大延迟不超过 100 毫秒，同时保证语音、触摸和显示响应。不能以平均 FPS 或 p95 替代这个门槛。

### 已确认的能力与问题

- 已盘点 49 个应用注册条目，找到通用检测、OCR、姿态、手部、分割、深度和本地视觉语言模型等资源；文件存在不等于加载及识别通过。
- 现有两个 EasyYolo App 引用的旧模型分别出现输出节点形状、输出张量索引错误。这属于适配兼容问题，不能作为内存或 NPU 容量不足的证据。
- 顶层当前姿态与物品模型可共同加载并执行。这些权重与旧 App 引用版本不同，不能用前者结果替代后者验收。
- 正式 KWS 仍为 2 线程。待唤醒短窗口 CPU 约占 1.65 个核心；未发现 CPU 配额限速证据，但尚未把全部延迟尖峰归因为单一原因。
- 正式配置下，单模型与双模型现场测试均出现真实语音不能唤醒；双模型停止后，用户确认语音恢复。因此正式配置下不能宣称整机共存验收通过。

### 临时单线程对照

仅通过临时运行配置将 KWS 从 2 线程改为 1 线程，模型及识别阈值保持不变。正式服务源码未永久改为单线程。

| 指标 | 临时 KWS 1 线程 + 两个 320×320 模型 |
|---|---:|
| 小智待唤醒 CPU | 约 0.57 个核心 |
| 持续测量 | 5 分钟 |
| 每模型平均更新率 | 约 25 次/秒 |
| 姿态模型最大软件延迟 | 25.20 ms |
| 物品模型最大软件延迟 | 70.77 ms |
| 滑动一秒窗口最低结果数 | 分别 24、23 |
| 固定音频唤醒 | 成功 |

这组结果通过了本轮**软件采集调用至推理完成**的候选基准。它尚不等于真实曝光到屏幕/其他设备的端到端 100 ms，也未完成该轮真实声音共存和长期稳定验收。

### 可视测试页

- 已建立固定双模型测试页，展示实时摄像头、姿态/物品彩色框、检测数量、置信度、模型名称与计时。用户确认看到了画面和识别框。
- 首版实显约 13 FPS，绘图中位耗时约 51.5 ms，未达到 20 FPS。
- 已完成内置字体与界面缓存优化，摄像头、识别框、类别、置信度和检测数仍按帧更新；统计文字低频刷新。
- 优化版已拷贝到设备，但尚未重开完成真机显示与性能复测，不能标为优化后通过。
- 最后一次在线回读（设计讨论前）已确认临时实验配置删除、正式 KWS 2 线程及桌面状态恢复；本次汇总不把临时配置当作正式发布默认值。日终再次连接设备超时，未能重新核验此刻的运行状态。

可视测试源保存于 [`examples/vision_model_test`](../examples/vision_model_test)，基准脚本保存于 [`tools/benchmarks`](../tools/benchmarks)。这些是实验工具，不是已注册的视觉 MCP；优化版实显仍待真机重测。

早期方法与数据见 [容量实测记录](VISION_CAPACITY_TEST_2026-10-25.md)。本页以上表作为单线程对照及可视化阶段的进度补充。

## 设计成果与下一阶段

离线模型调用采用能力目录、受管任务和资源仲裁；打开已有 App 与取得识别结果分别设计。运动判断需要连续帧与时序规则，不能把静态站立/坐下/躺下直接解释成锻炼或摔倒事件。

小智通过 SIoT MCP 控制启动、配置和停止；高频识别帧由设备本地直接通过 MQTT 发布，接收设备订阅。该方案仍未实施，详见 [视觉结果与 SIoT 设计](VISION_SIOT_DESIGN.md)。具体工作顺序见 [下一步任务](NEXT_STEPS.md)。
