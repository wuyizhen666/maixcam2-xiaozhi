# MaixCAM2 独立 SIoT 服务与触屏监控

更新：2026-10-26。服务器运行在 MaixCAM2 上，PC 只是可选的浏览器或 MQTT 客户端。设备供电并接入局域网后，SIoT 收发与本机触屏监控不依赖 PC 或互联网；云端小智对话仍需外网。USB 网络地址仅在连接 PC 时适用。

## 最新界面方案与验证状态

用户已现场确认此前版本的基本显示、输入、发送和退出正常。完整日期时间已在真机查看，蓝色“退格删字”按钮用于删除光标前一个字符，中文、英文、数字逐字删除经界面事件验证。

主题/图表布局已有真机记录；媒体摄像头与小智拍照识别转发已有真机数据，清空数据、图片识别界面及资源退出仍在验证。当前界面定义如下，各项验证范围见“验证记录与边界”：

- 左侧保留主题列表，原上一页/下一页按钮改为“新建主题”和“删除主题”。删除前二次确认，并显示完整主题名；删除会连同该主题历史一起删除。
- 左上提供搜索、清除筛选和刷新。两侧列表通过滑动或拖动滚动条浏览，点击在松手时触发，避免滑动过程误选主题或打开消息。
- 右侧底部依次为“消息”“图表”“图像/视频”和缩小后的“编辑/发送”。纯数字消息以折线显示，并列出最新值、最小值和最大值；非数字或混合消息提示切回消息视图，不捏造或补零生成数据点。
- 右侧顶部“清空数据”经完整主题名二次确认后清除历史与旧缓存、保留主题，新收到的消息继续显示。它与删除主题是不同操作。
- “图像/视频”进入来源二级页：所选 MQTT 主题图片、局域网收发、MaixCAM2 本机摄像头。局域网收发再进入三级页，选择接收 HTTP 图片/MJPEG/RTSP，或显式开启本机摄像头 HTTP 共享。摄像头另可单帧或连续向 MQTT 主题发送，协议与连接方式见 [媒体说明](SIOT_MEDIA.md)。
- 本机摄像头发送前选择 JSON / Base64 与 2 / 5 / 10 fps（默认 5），切换先停止旧会话，两格式均可配置当前会话速率。“Base64”实际发送完整 Data URL，当前 Mind+ 版本已确认带 `data:image/jpeg;base64,` 前缀正常，裸 Base64 破图；MaixCAM2 接收器仍自动兼容裸 Base64。

消息列表与详情使用设备本地时区显示完整 `YYYY-MM-DD HH:MM:SS`；实时消息是本机接收时间，历史消息是服务器记录时间。图表保留数据时间，同秒记录不会被人为分配不同时间间隔。

本次 LAN 地址为 `192.168.50.120`，浏览器可访问 `http://192.168.50.120:8080`；USB 网络可使用 `http://10.173.120.1:8080`。地址可能随网络变化，应以设备实际地址为准。

`8080` 是 SIoT 管理/历史页面，不是连续视频页面。开启“图像/视频 → 局域网收发 → 发送端”后，浏览器可用 `http://设备地址:8090/` 看预览；另一台接收端填写完整 `/stream.mjpg` 地址，`/snapshot.jpg` 提供原 JPEG，`/status.json` 提供状态。发送端最多 4 个媒体/8 个总连接、10 fps 上限，无录像或持久存储，退出停止服务器和摄像头。它提供 HTTP/MJPEG，不提供 RTSP server。原生发送页和单 PC 跨 LAN 取图已验证；原生接收端手工输入 URL 的完整流程与浏览器网页视觉仍需独立验证。

服务使用独立的 `siot` 系统账号。安装程序生成该设备自己的证书与密钥，没有沿用分发包中的私钥，也没有安装旧版 Python SIoT 客户端或降级现有 Paho MQTT 2.x。

## 在另一台设备上初次安装

以下命令在设备上执行。先将已经核验的内层归档、`tools/siot/` 和必要源码上传到受控暂存目录。示例暂存目录为 `/tmp/siot-install-2618`。

1. 确认是 AArch64，且 1883、8080、1888、8883 未被其他服务占用；确认 `/opt/siot`、`/var/lib/siot` 和同名单元不存在。安装器遇到已有部署会停止，不能用它直接覆盖升级。
2. 使用项目安装器安装归档，不运行供应包脚本：

   ```sh
   python3 /tmp/siot-install-2618/tools/siot/install_server.py \
     /tmp/siot-install-2618/server.tar.gz \
     --sha256 8af7fedfea02ecffa724c34edd74db4e03b0dce2df9208be62113e542b7a612f
   ```

3. 按 `apps/siot_monitor/connection.example.json` 建立 `/etc/siot/monitor.json`，填入服务器实际有效的账号与密码。文件归 root 所有，权限设为 `0600`。本机连接使用 `127.0.0.1`，默认主题使用 `实际账号/monitor`。不要把凭据写入命令行参数、代码或日志。
4. 运行验证程序。它会建立唯一的账号所属测试主题，发送测试消息，并回读历史；不是只读检查。

   ```sh
   mkdir -p /tmp/siot-install-2618
   python3 /tmp/siot-install-2618/tools/siot/verify_server.py
   systemctl enable siot.service
   systemctl is-active siot.service
   systemctl is-enabled siot.service
   ```

   初始安装器只启动服务，功能验证通过后再启用自启动。验证结果保存在 `/tmp/siot-install-2618/verification.json`。另需测试服务重启后的历史保留；自启动已启用不等于已经做过断电启动测试。

5. 安装监控 App 前回到应用桌面，确保没有相机或其他 App 占用前台。暂存目录保留 `apps/siot_monitor/` 与 `xiaozhi/service/` 的仓库相对结构。先分别对**已核对的旧版** `/root/xiaozhi/xiaozhi_service.py` 和 `/root/xiaozhi/hardware_tools.py` 计算 LF 换行归一化后的 SHA-256，传给安装器防止覆盖未知版本；两个参数均为必填：

   ```sh
   python3 /tmp/siot-install-2618/tools/siot/install_monitor.py \
     /tmp/siot-install-2618/stage \
     --expected-service-sha256 <已核对的旧版服务SHA256> \
     --expected-hardware-sha256 <已核对的旧版硬件适配SHA256>
   ```

   安装器会备份旧服务文件与 App 注册表，同步 `xiaozhi_service.py`、`hardware_tools.py`、`ui_ownership.py`、`camera_ownership.py`、`vision_siot.py`，并为 App 放置两个所有权辅助模块及媒体源码（包括 `lan_camera_server.py`）；`xiaozhi/deploy.sh` 同样包含视觉转发模块。它停止小智后重启桌面，等待桌面持有 DRM 显示设备，再启动小智；异常时恢复本次已备份的服务文件和注册表。初装器拒绝覆盖已有监控 App，已有设备升级需单独备份并同步整组适配文件。不要绕过版本检查，也不要把运行中的当前源码哈希当作未经审查的升级授权。

## 消息与保存语义

保存开启时，编辑器要求完整主题属于当前账号，例如 `alice/monitor`。后台通过 `PUT /api/v2/topics` 以相对名称 `monitor` 登记主题，核对服务器返回的完整名称后，再以 QoS 1 发布。服务器会自动添加账号前缀；把完整名称再次传给创建接口会导致前缀重复。

仅指定 QoS 1 不足以保证未登记的主题进入历史。界面中的服务器确认表示 broker 接收与保存请求，持久化是否成功仍以历史回读为准，也不代表 ESP32 等订阅端已经执行动作。保存关闭时使用 QoS 0 转发，允许普通具体主题；两种模式都不发送 retained 消息。

QoS 1 消息恰遇断线且 Paho 已接受排队时，保留发送请求并等待重连确认，不误报未发送或自动重复发布。离线状态下拒绝新的发送请求。

主题删除接口已用一个唯一临时主题在真机核对：`DELETE /api/v2/topics/{numeric_id}`，请求不带正文。删除前该主题历史为 1 条，删除后为 0 条，说明删除主题同时移除历史。后续界面测试也已核对取消保留、二次确认删除及历史清空，测试范围仅限专门新建的临时主题。

最新“清空数据”通过 `POST /api/v2/messages/delMsgByTopic` 提交完整主题名，核对原历史 ID 消失且主题 ID 保持不变；清除旧缓存后继续接收新消息。该功能有独立二次确认，不使用删除再重建主题来模拟清空。独立真机 API 验证已确认历史清除且主题 ID 保留；取消确认与保留新消息有主机测试，完整触屏操作仍待补验。

原有小智拍照 MCP 已接入异步 SIoT 转发：拍摄时先发布原图，云识别结束后以相同 `capture_id` 和原始 JPEG 更新 `recognition`，另发 `vision_result` 的文字和状态，不等待 SIoT 确认且保持原 MCP 云识别返回值。默认使用 `username/vision/image`、`username/vision/result`；监控配置中的 `vision_image_topic`、`vision_result_topic` 可覆盖，小智配置 `siot_vision_publish: false` 可关闭。原图上限 2 MiB、图片信封 3 MiB、识别文字 256 KiB；连续摄像头 JPEG 发布仍限 512 KiB。协议与屏幕截断边界见 [媒体说明](SIOT_MEDIA.md)。

## 与小智共存

监控 App 通过临时 UI 所有权文件 `/run/xiaozhi-ui-owner.json` 协调显示和触摸。前台监控期间，小智弹窗与触摸唤醒让出界面，后台语音服务继续运行；不会持久修改 `popup_enabled` 或 `touch_wake`。所有权以进程 PID、启动时间和租约 ID 校验，进程结束后清理，陈旧进程记录不继续占用界面。

监控主界面不创建音频对象。最新本机摄像头来源由独立进程采集，通过 `camera_ownership.py` 的协作锁与小智拍照互斥；第三方原生相机 App 不参与该锁，不能当作全系统摄像头复用机制。切换来源或退出媒体时停止发送并释放摄像头。显示初始化必须先于小智音频初始化，维护时保持“停止小智 → 重启桌面并确认显示就绪 → 启动小智”的顺序。

本次启动器兼容修复仅调整 `launch.py` 顶层成功退出方式：将 `sys.exit(main())` 改为接收 `main()` 返回值，成功时自然结束，非零时抛出 `RuntimeError`，保留失败可见性。此前 GUI 子进程已返回 0，但桌面仍弹出 `code:-1`；上述单项调整后，退出与重开验证通过。这是当前 Maix 应用启动路径的兼容要求，不代表所有 Python 程序都不能使用 `sys.exit(0)`。

## 维护与回滚

查看状态使用 `systemctl status siot.service`，日志使用 `journalctl -u siot.service`。日志或截图可能包含消息内容，应只保存在本地受控目录。停止监控页面不应停止 SIoT 服务；需要暂停服务器时使用 `systemctl stop siot.service`，禁用自启动使用 `systemctl disable siot.service`。

备份数据库前先停止 SIoT，完整复制 `/var/lib/siot`，并保护配置和密钥；备份完成再启动服务。不要只复制运行中的 SQLite 主文件而忽略可能存在的 WAL 等配套文件。服务器回滚应恢复匹配版本的程序、配置及数据库备份，避免直接删除数据。

App 安装备份位于 `/root/xiaozhi_backups/siot-monitor-时间戳/`。回退 UI/摄像头集成时，先退出前台 App，停止小智和桌面，恢复同次备份的 `xiaozhi_service.py`、`hardware_tools.py` 与 `app.info`；备份中存在 `ui_ownership.py`、`camera_ownership.py`、`vision_siot.py` 时也一并恢复。保留新旧文件清单，不能只退回界面而留下不匹配的硬件适配；从无这些辅助模块的旧版回退时，先确认引用已消失再处理新增文件，不自动删除。再次按桌面先于小智的顺序启动并检查服务。恢复旧注册表会撤销这次添加的入口；若其后安装了其他 App，先比较注册表，避免覆盖后续变更。保留 App 文件和 SIoT 数据便于排查。
