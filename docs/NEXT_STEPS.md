# 下一阶段任务

更新日期：2026-10-27。小智与硬件基线见 [开发汇总](DEVELOPMENT_SUMMARY_2026-10-25.md)，新增 SIoT 服务、触屏监控与图片传输见 [部署说明](SIOT_DEPLOYMENT.md) 和 [媒体说明](SIOT_MEDIA.md)。本清单是后续计划，不代表已经实现或验收。

SIoT 媒体部分用户已反馈基本可用。后续先补第二台接收设备、真人语音与连续画面共存、断电启动、长期资源释放，以及清空数据/URL 接收的完整触屏验收。每轮开始重新核对设备状态，不以历史在线记录代替当前检查。

## 1. 先完成可视化与共存验收

| 任务 | 完成条件 |
|---|---|
| 重开优化后的视觉测试页 | 实际画面、识别框、模式切换、返回操作正确；保存新的软件计时摘要 |
| 复测临时 KWS 1 线程 | 现场开始确认后再计时，包含真实语音唤醒、完整回答、X 退出、再次唤醒及触摸操作 |
| 重新测量两模型和显示 | 每模型滑动一秒窗口至少 20 个结果；所有已测软件结果延迟不超过 100 ms；同时报告显示提交率、最长间隔和超限次数 |
| 验证帧新鲜度 | 区分本地帧序号与传感器帧；检查缓存积压，补光学或等价外部事件到结果的端到端测量 |
| 延长稳定性观察 | 在上述门槛通过后延长运行，检查内存趋势、温度、相机释放、音频欠载和异常退出恢复 |

单线程双模型已通过 5 分钟软件候选基准，但不能直接永久替换正式配置。确认真实语音、实显与资源恢复后，再决定是否将单线程作为默认设置。

测试每次必须标明：源码版本、模型版本、输入分辨率、是否限频、是否绘屏、是否使用真实麦克风、是否临时配置。平均 FPS、p95、进程存活、资源回收都不能单独代替完整验收。

## 2. 解决旧 App 模型适配

- 固定现有 App 实际引用的模型版本，核对完整依赖、输出节点、标签顺序及前后处理。
- 分开处理“加载失败”和“首次推理失败”；不要未经记录地换成另一个同名模型。
- 用固定图片验证类别和框坐标，再验证真实相机输入；随后验证 App 打开、退出、显示、触摸以及小智共存。
- 一个 App 通过不能推广为所有已安装 App 通过；仅可启动的 App 与可返回结构化结果的 App 分别标记。

## 3. 接入离线视觉 MCP

当前尚未注册离线视觉、App 启动或通用视觉流 MCP 工具。小智云端拍照已能自动向 SIoT 转发原图与识别结果，监控 App 已支持连续图片；它们不等同于离线推理 MCP。建议实施顺序：

1. 建立只读能力目录，区分发现、依赖完整、可加载、可推理、已通过 MCP 验证。
2. 建立单摄像头所有权与受管视觉任务，包含加载、预热、观察、完成、取消、错误和恢复状态。
3. 选定一个已验证模型完成语音→MCP→本地推理→结构化结果→屏幕/语音闭环。
4. 接入双模型组合及固定结果显示，保持同帧关联；网络操作不得阻塞推理。
5. 再接入已验证的 App 启动/返回桥和结果适配器。

必须覆盖：任务并发冲突、超时、模型损坏、会话断开、重复请求、用户关闭、晚到结果、工作进程退出后硬件未恢复等情况。不能仅取消 Python 任务便宣称原生硬件调用已停止。

## 4. 运动观察与 SIoT

按 [视觉结果与 SIoT 设计](VISION_SIOT_DESIGN.md) 推进：

- 先确定是检测一般人体活动，还是识别指定锻炼动作；明确首批动作、观察时长和无法判断条件。
- 优先复用人体关键点模型与本地时序聚合；现有静态姿态/物品组合不能直接证明人在锻炼。
- 复用已部署 SIoT 服务和已核验主题规则；通用 SIoT MCP 仍待实现，接收设备消息容量仍需逐台验证。
- 完成控制命令、状态确认、逐帧数据、事件摘要四条主题契约，再做接收端订阅与回执。
- 端到端测量必须包含采集、推理、发布排队、传输和接收处理；丢旧保新与逐帧可靠留存作为不同模式验收。

## 5. 保留的延期项

- 通用 UI MCP 仍暂停；固定视觉测试页不应扩展为未计划的动态 UI 框架。
- 外接 GPIO/I²C/SPI/UART 的真实模块通信按用户约定延期；继续保持默认拒绝及显式资源白名单。
- 用户状态 LED 的肉眼观察暂缓，不能把驱动回读写成光学验收。
- ADC 电压换算、RTC 校时、完整动作数据集准确率和长期运行均未完成。

## 每轮结束检查

- 关闭本轮创建的模型进程，确认相机与显存/硬件内存释放。
- 确认前台回到预期界面，再按已有显示先于音频的要求处理服务启动。
- 恢复临时 systemd 配置、线程数、弹窗和音量设置，并核实正式源码未被实验覆盖。
- 记录成功、失败、未验证项；公开交付仅保留脱敏指标，不包含原始语音、画面、日志或凭据。
