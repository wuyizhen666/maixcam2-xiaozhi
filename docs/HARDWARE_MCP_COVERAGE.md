# MaixCAM2 硬件 MCP 覆盖检查

日期：2026-10-25。目标：当前设备 `maixcam2-test-device` 上的小智服务。

结论：**当前注册29个MCP工具，新增板载LED、按键、IMU、RTC、ADC原始读取，以及受控外部I/O接口；外接设备通信与其余整机功能仍不能宣称全部完成。** 不使用任意硬件分组数量计算“完成百分比”。

当前外设实施与验收见 [外设接入记录](PERIPHERAL_MCP_VALIDATION.md)，配置方法见 [外部I/O访问配置](IO_ACCESS.md)。下方最初10项清单和检查方法保留为此前基线，完整当前清单见 [MCP清单](MCP_CAPABILITIES.md)。

## 最初基线如何核对

1. 在设备独立进程中只读执行已部署 `McpServer` 的真实 `tools/list` 处理函数，捕获返回值：10项、无下一页。没有执行任何修改硬件的工具回调。
2. 比对已部署服务、hardware_tools、ui_render、ui_feedback与本地源文件SHA256，全部一致；服务处于active/running。
3. 阅读当前注册与调用路径，没有发现额外动态append/extend硬件工具的机制。
4. 只读枚举设备节点、sysfs、输入设备、块设备，对照Sipeed官方硬件表。

这不是向正在运行进程发送一次云端tools/list网络请求；注册清单证据来自同一部署代码的处理函数与源文件/运行状态核对。此前这10个工具在本会话已有分阶段实际调用记录，本次没有重新逐一操作硬件。

硬件存在、Linux驱动节点存在、MaixPy能用、已经封装MCP、实际MCP调用成功，是不同证据层级；下表分别说明。

## 最初10个基础工具（另有16个扩展工具）

| 工具 | 参数 | 功能 |
| --- | --- | --- |
| `self.audio_speaker.set_volume` | volume: integer 0–100 | 设置音量 |
| `self.audio_speaker.get_volume` | 无 | 查询音量 |
| `self.audio_speaker.get_volume_status` | 无 | 查询音量/静音标记 |
| `self.get_device_status` | 无 | 小智会话、网络可用、激活、音量、唤醒词、运行时间 |
| `self.display.show_message` | message: string | 显示文字消息 |
| `self.camera.take_photo` | question: string | 拍照、3秒预览、云端视觉分析 |
| `self.camera.get_status` | 无 | 视觉配置、拍摄任务和最近上传状态 |
| `self.light.set_power` | enabled: boolean | 补光灯开关 |
| `self.light.set_brightness` | brightness: integer 0–100 | 补光灯调光 |
| `self.light.get_status` | 无 | 补光灯驱动状态/亮度 |

状态工具的含义不能扩张：camera.get_status不是传感器全面自检；audio_speaker.get_volume_status中的available目前固定为true；get_device_status没有返回CPU、内存、电池、IMU、存储或全部接口健康信息。

| --- | --- | --- | --- |
| 摄像头 | MCP拍照、云端识图、状态；内部自动AE/AWB预热、3秒预览 | 基础功能已接入并实测 | 无录像/视频流、多相机选择、分辨率/曝光/WB参数MCP工具 |

| 六轴IMU | LSM6DSOWTR加速度/角速度读取 | 已接入并做静止/改变朝向实测 | 未做零偏校准；温度返回null |
| RTC | 读取RTC UTC时间、系统时间和差值 | 只读已接入并实测 | 不提供校时/闹钟写操作 |

| Wi-Fi | wlan0为up，现有小智内部联网 | 仅汇总网络可用状态 | 无SSID/RSSI、扫描、连接配置等专用MCP |
| 蓝牙/BLE | 检测到hci0 | 未接入 | 无扫描/连接/GATT等MCP，未做无线链路测试 |
| 以太网接口 | eth0存在，当前down；RJ45需要扩展模块 | 未接入 | 未验证外接模块/网线，不因down判故障 |
| USB Host/Device | usb0/usb1为up，目前USB网络/SSH在用 | 未封装专用MCP | 无USB模式切换或USB外设控制工具 |
| eMMC/TF存储 | 检测到29.1G主块设备及其分区；内部保存程序、模型、状态 | 未封装存储MCP | 无容量/文件管理/录像保存工具；本轮未验证TF卡是否插入 |
| GPIO/PMOD | 配置目标、白名单读写、复用与占用检查 | 受控接口已实现，默认关闭 | 当前A4复用无法确认，实机验证为安全拒绝；未做外接电气验证 |
| I²C | I2C6/7逻辑目标、8位寄存器白名单读写 | 受控接口已实现，默认关闭 | 内部总线禁用；未知复用拒绝；无目标外设通信验证 |
| SPI | 仅spidev2.1、受控模式/速率/长度收发 | 受控接口已实现，默认关闭 | 空接口控制器1字节收发通过，不代表外设协议通过 |
| UART | 仅UART2、受控波特率和有界收发 | 受控接口已实现，默认关闭 | 驱动接受1字节、无对端读超时验证；未做外设协议验证 |
| PWM | 检测到pwmchip0/4/8 | 仅补光灯PWM6已接入 | 无其它PWM通道/舵机控制MCP |
| ADC | Linux IIO 0–3路原始计数 | 已接入并四路实测 | 未校准量程，不换算电压，不代表已确认外接ADC引脚 |
| 看门狗WDT | 官方规格提供此类外设 | 未接入 | 未打开/配置看门狗设备；没有MCP工具 |
| NPU/本地AI | 平台具备NPU；当前视觉分析走云端 | 未封装本地AI工具 | 无本地检测、分类、姿态、OCR/本地模型推理等MCP |
| 视频编解码 | 官方规格支持H.264/H.265/MJPEG等 | 未接入视频MCP | 无硬件录像、视频编码或直播工具；JPEG拍照不代表视频接口已覆盖 |
| CPU/内存/温度/小核 | 系统用于运行应用 | 未封装全面系统诊断MCP | 无负载、温度、内存、存储健康、小核任务状态工具 |

外接ToF、热成像、舵机、扩展传感器不作为“本机已安装硬件”假定；需按实际装配另行列清单。没有/dev/video节点也不能判定相机缺失，本机相机通过Maix私有驱动工作且已经实际验证。

## 当前状态与后续范围

本次只读检查结束，小智与launcher均active/running，enabled=true，音量100；没有新增工具、改变硬件设置或启动新的硬件测试。

如后续要补齐覆盖，应先定义每个硬件要开放的具体动作。例如麦克风状态/增益、屏幕亮度、IMU读数、电池状态、RTC读取可以作为独立功能项；“所有硬件全部MCP化”不能仅靠增加一个通用get_device_status来完成。

完整只读证据：本地 `.runtime/hardware-mcp-audit/inventory.json`。不包含Wi-Fi密码或小智凭据。

硬件资源依据：[Sipeed MaixCAM2 官方硬件表](https://wiki.sipeed.com/hardware/zh/maixcam/maixcam2.html)。官方标称能力用于确定检查范围，设备节点与此前实测用于描述当前证据，二者没有互相替代。
