# 拍照预览与 MCP 名称显示验收

日期：2026-10-25。设备：`maixcam2-test-device`。本次是在已完成摄像头/补光灯接入的基础上增量更新；MCP 工具总数仍为 10 个。

## 使用效果

- 成功拍到 JPEG 后，立即把同一张照片等比例显示在顶部操作条与底部提示条之间，不裁切画面。3 秒后主动清除照片并恢复聊天，不需要等待下一条消息。
- 拍摄预览与视觉服务上传并行，预览不会等待网络分析完成。
- MCP `tools/call` 执行期间底部显示完整工具名，如 `self.camera.take_photo`、`self.light.set_power`。执行结束后再保留 3 秒，快速完成的工具也能看清。
- 连续拍照以最新照片重新计时；旧定时器不会清掉新照片。关闭弹窗、关闭小智或结束会话会立即清理临时反馈，旧会话的迟到拍摄回调不会重新弹出。
- 仍遵守现有“弹出聊天窗口”开关；关闭该开关时不显示这些弹窗反馈。

本轮语音指令采用固定 WAV 注入，验证真实云端 MCP 与设备显示流程；不据此推断真人语音识别准确率。屏幕证据来自实际 launcher 合成帧，不是仅凭应用状态标记。

## 修复的显示刷新问题

第一轮 Python 状态虽然记录到照片预览，但实际合成帧仍为聊天。原因是原 `load_overlay()` 只比较秒级 mtime 和固定文件大小，同一秒内的原子替换可能被忽略。

先用实际 C loader 的原生测试复现失败，再将缓存键扩展为 mtime 秒/纳秒、inode 和大小。复测屏幕像素确认照片确实出现并消失。

原生测试包含生产 C 文件，但在链接前通过 objcopy 去掉测试对象的构造器注册，避免测试初始化触摸设备。产品库仍按原方式编译、运行。
