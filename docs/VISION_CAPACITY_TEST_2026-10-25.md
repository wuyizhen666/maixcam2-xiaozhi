# 小智与离线视觉模型共存容量实测

本文保留早期正式配置测试。后续单线程KWS对照、可视App实显及未完成事项以[日终汇总](DEVELOPMENT_SUMMARY_2026-10-25.md)为准；不能将本文早期失败结论或后续软件基准通过推广为完整光学端到端通过。

日期：2026-10-25。设备 maixcam2-test-device。验收要求：每模型稳定至少20次/秒、延迟不超过100毫秒，同时保持整机响应。

## 当前结论

已验证两个320×320轻量模型能与小智共同驻留并持续推理60秒，资源可回收。但没有任何已测组合通过完整实时性要求：单个通用模型有低于20Hz窗口；两个轻量模型有超过100ms的延迟尖峰；小智在共存测试中出现超过1秒事件循环卡顿。

这不是“硬件最多只能运行两个模型”的结论，也不是“只能运行零个模型”。它表示当前部署下，尚无经过本轮验证、可承诺满足指定实时标准的配置。已停止第三个模型增压。

## 方法和边界

- 保留原小智、launcher进程与产品代码，使用/tmp独立测试进程。
- 多模型共用相机、同时驻留，同一帧按顺序推理；dual_buff=False。
- general为640×480；两个current自定义模型均320×320。
- 预热独立记录。表中是预热后持续测量，冷启动首结果另约4.6～5.2秒，不能把启动耗时隐藏为低于100ms。
- 延迟从camera.read调用开始计到对应模型推理完成，包含读取等待和同帧前序模型推理；不包含此前传感器曝光、ISP队列，也不包含屏幕扫描显示。因此只是软件路径测量，尚未证明光学端到端≤100ms。
- 频率同时检查全程平均和约1秒完整窗口，不以平均值替代稳定更新。原始逐帧样本保留。
- 测试进程未绘制实时识别画面，不能把该测试直接当作GUI App或触摸实时性验收。
- 自动WAV测试部分语句被截断，预设查询音量流程未完整复现；日志存在实际MCP调用和语音回复，但不能据此宣称真实麦克风唤醒/语音闭环全部通过。
